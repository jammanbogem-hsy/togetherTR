- 작성: ui-designer (team `tcid-ui-redesign`)
- 날짜: 2026-04-14 · v1.2 갱신 (라이브 인디케이터 §11 신설)
- 관련 파일: `src/app/globals.css`, `src/components/stage/StageBar.tsx`, `src/components/activity/ActivitySidebar.tsx`, `src/components/artifacts/ArtifactPanel.tsx`, `src/app/(app)/projects/[id]/page.tsx`

**"완료"의 단일 판정 기준 (3영역 공유 규칙 — v1.1 신규)**:
- 활동 status = `completed` **AND** 산출물 status = `confirmed` → 시각적 "완료" 인정
- 둘 중 하나만 성립 시 → `warning` 처리 (교사에게 불일치 표면화)
- ActivitySidebar의 `effectiveStatus` 로직이 이미 일부 구현 — StageBar 진행률 카운터와 ArtifactPanel 완료 표기도 **동일 헬퍼 사용** 필수 (`src/lib/activity/completion.ts::isEffectivelyDone`)

**구현 주의**: `active_return`은 기존 ActivitySidebar `effectiveStatus` 매핑과 정합성 맞춰야 함. ArtifactPanel에서도 동일 아이콘·색 재사용 + 본문에 "재검토 중 — 기존 합의안 확인 후 수정 근거 기록" 배너 표시 (v1.1 신규).

## 4. Elevation · Border · Radius

### 4-1. Elevation (globals.css 기존 3단계 사용)
- `md-shadow-1`: 패널·사이드바 기본
- `md-shadow-2`: hover, 떠오름
- `md-shadow-3`: 모달, 팝오버
- **신규 사용처**: ArtifactPanel 카드 hover 시 `shadow-1 → shadow-2` 전환. Sidebar 활동 row는 shadow 쓰지 말고 `bg + inset` 변화로만 피드백 (실제는 `shadow-sm` 한 번과 `activity-glow` 애니메이션만 붙이고 있음).

### 4-2. Border
- Panel 외곽: `border border-[#DADCE0]` + `rounded-2xl(16px)` — 3영역 공통
- 카드 내부: `border border-[stage.border]` (연한 파스텔) + `rounded-2xl`
- Checklist 요구 섹션 카드: `border-2` (이미 사용, 유지) — **2px는 "충족 여부 판정 중"** 의미를 내포하므로 다른 곳에서 `border-2` 남발 금지
- Divider: `border-t border-[#F1F3F4]` (연한 회색, 경계 느낌만)
- 포커스 시 inset shadow로 강조 (양방향 강조 느낌 — **실제 구현은 `box-shadow: inset 0 0 0 2px var(--primary)` 한 줄**, 추가 ring 없이)

### 4-3. Radius
- 버튼 pill: `rounded-full`
- 카드: `rounded-2xl` (16px) — 3영역 루트, 정보 카드
- 소형 카드·뱃지: `rounded-xl` (12px)
- Morph 버튼(단계 분석하기 등): `morph-btn` 클래스 유지 (비정형)
- Stage Chip: **기하 radius 없음**, `morph-shape` 애니메이션이 대체

### 4-4. Corner Decoration (기존 유지)
`corner-wrap-sidebar / chat / artifact` 는 영역별 **포지션·크기 대비**로 이미 공간 구분을 수행 중. 이번 업그레이드에서 건드리지 말 것. hover 시 corner 확장 속도가 3영역 모두 다른 것도 **의도된 차이** (Sidebar 0.65s / Chat 0.9s / Artifact 0.5s).

## 5. 상태 전환 (모션)

### 5-1. Duration·Easing 규칙
- 즉각 반응 (버튼 press, hover 색 변화): `duration-150` `ease-out`
- 요소 이동·크기 변화 (패널 접힘/펼침, hover 스케일): `duration-200~300` `cubic-bezier(.4,0,.2,1)` (MD standard)
- Glow·idle 애니메이션 (무한 반복): `2~3s ease-in-out infinite` — **전역 리듬 유지** (stage-bounce 2.8s / activity-glow 2s / morph-shape 7~11s)
- 유기적 morph-shape: 단계별 **delay가 다르게** 걸려 있어 5개 단계가 동시에 같은 모양이 되지 않음 (StageBar `STAGE_MORPH_DELAY`). 이 delay 시퀀스는 **반드시 유지**.

### 5-2. 접힘 ↔ 펼침 (page.tsx layout 토글)
| 상태 | Sidebar | StageBar | ArtifactPanel |
|---|---|---|---|
| 펼침 | `w-80` | `py-3` 정상 | `w-[418px]` |
| 접힘 | `w-10` + 세로 코드 표시 | `h-10` 스트립 + "현재 단계" mini | `w-10` + 아이콘 |
| 전환 | `transition-all duration-300` | 동일 | 동일 |

접힘 상태에서도 "현재 어느 활동/단계"인지는 **반드시 읽을 수 있어야** 함 (세로쓰기 코드, mini label). 이 원칙은 3영역 area owner에게 동일 적용.

### 5-3. Hover 상태
- 활동 row: `bg-[#F1F3F4]` (surface-variant) → viewing이면 `#E8F0FE` + glow
- 버튼 pill: `bg` 한 단계 진해짐 (예: `#E8F0FE → #D2E3FC`)
- 카드: `shadow-1 → shadow-2`, `translate-y` 금지 (페이지 레이아웃 흔들림 유발)
- 단계 chip: `hover:scale-105 active:scale-95 transition-transform duration-150`

### 5-4. Focus Ring
- 키보드 포커스: `outline-none` + `box-shadow: 0 0 0 2px var(--surface), 0 0 0 4px var(--primary)` 2층 링 (배경과 구분되는 흰 인셋 + primary 외곽)
- 단계 chip의 경우 포커스 링은 morph-shape을 깨뜨리므로 **아이콘 주변 원형 링**으로 대체: `ring` 대신 `filter: drop-shadow(0 0 3px var(--primary))`.

## 6. 접근성

- **명암비**: 본문 텍스트 `#202124 on #FFFFFF` = 16.1:1 ✓. 보조 텍스트 `#5F6368 on #F8F9FA` = 5.8:1 ✓. **연한 stage light 배경 위의 stage text는 `opacity-70`으로 낮추지 말 것** — 현재 ActivitySidebar 목표문 `opacity-70`은 4.5:1 경계이므로 유지는 가능하나 **신규 추가 UI에서는 안 함**.
- **최소 터치 타겟**: 36×36 (현재 chip 미진행 `w-9 h-9` 가 하한, 이보다 작은 활동 상태 아이콘 16px는 row 자체가 클릭 영역이므로 OK).
- **키보드 네비**: 단계 chip / 활동 row / 패널 토글 모두 `<button>` 요소. `Tab` 순서: StageBar → Sidebar 헤더 → 활동 리스트 → 분석 버튼 → ArtifactPanel 헤더. `Esc`는 모달·팝오버(멤버 리스트) 닫기.
- **스크린 리더**: 상태 전달은 **아이콘 의존 금지**. `aria-label` 또는 텍스트 라벨 중복 필수. 예: `<CheckCircle />`만 있는 경우 옆에 시각적 라벨이 없으면 `aria-label="확정됨"` 추가.
- **모션 축소**: `prefers-reduced-motion: reduce` 미디어쿼리로 `morph-shape`·`activity-glow`·`stage-bounce`·`chevron-flow`를 **모두 정지**시키는 규칙을 globals.css 하단에 추가 (이번 업그레이드 필수 작업, ui-designer가 StageBar 업그레이드 PR에 포함하도록 가이드).

## 7. 3영역별 정보 계층

각 영역이 **사용자에게 가장 먼저 말해야 할 것**의 우선순위. area owner는 이 순서를 UI 상에서 시각 크기·위치·색으로 반영.

### 7-0. 교수학 3축 (v1.1 신설 — pedagogy-auditor 제안)

3영역은 각자 다른 **교사의 "왜" 재구성 층위**를 담당. 단순 탐색 위젯이 아닌 교수학적 사고 지지 구조.

| 영역 | 교수학 축 | 교사가 얻어야 할 "1번 정보" |
|---|---|---|
| 상단 StageBar | **전체 궤적 인식** (모형 차원) | "나는 T-CID 주기 중 어디에 있고, 이 단계가 전체 설계에서 왜 필요한가" |
| 좌측 ActivitySidebar | **단계 내 순서·연결** (단계 차원) | "이 단계의 활동들이 어떤 논리로 이어지며, 지금 활동이 왜 이 시점에 오는가" |
| 우측 ArtifactPanel | **산출물 간 누적·제약** (활동 차원) | "지금 작업이 이전 산출물을 어떻게 계승하고, 이후에 어떤 제약이 되는가" |

세 영역 모두 "진행률 바 이상"이어야 한다. area owner는 아래 §7-1~§7-3의 **신규(v1.1)** 항목을 필수 구현.

### 7-1. 상단 StageBar (team-lead)

기존 시각 뼈대 유지:
1. **"지금 어느 단계"** (현재 단계 chip이 가장 크고 morph + pulse)
2. **"전체 여정 어디쯤"** (5단계 chevron flow로 방향 제시)
3. **이 단계 진행률** (활성 chip 내부 세로 fill + `x/n` 카운터; 기준은 §1-3 단일 판정)
4. **주기 전환 가능 여부** (E→T CycleArrow 라벨 버튼)
5. 완료 단계는 **되돌아갈 수 있다는 힌트** (hover:scale, title 속성)

**v1.1 신규 (pedagogy-auditor 반영)**:
- **6. 노드 호버 tooltip — 단계 교육적 명제 1줄** (필수): 예 "A = 수업의 뼈대 — 이 단계 산출물이 Ds의 제약이 됩니다". tooltip 내용: 단계 정의 + 대표 활동 2~3개 + 가드레일 "생성/소비" 표식 + (호스트 한정) 이동 버튼.
- **7. Ds 노드에 백워드 설계 ★ 코너 배지** (필수): 현재 사이드바 범례에만 있는 "평가 먼저"를 `#F9AB00` Star를 Ds chip 우하단 코너에 작은 배지로 노출 (실제는 `absolute -bottom-1 -right-1` + `w-4 h-4 rounded-full bg-[#F9AB00]` 내부에 Star 10px).

- **9. 가드레일 배지를 A 단계에도**: 현재 Ds chip에만 있는 Shield 배지를 A-2-3 완료 시 **A chip에도 동일 표식** — "여기서 가드레일이 만들어졌다" 신호.
- **10. E→T 호버 안내**: CycleArrow 라벨 호버 시 "E-2-1 팀 성찰이 다음 T-1-1의 입력이 됩니다" tooltip (실제는 기존 `title` 속성을 확장 tooltip 컴포넌트로 승격).

**크기 계층 재조정 (v1 유지)**: 현재 완료 `w-10` / 미진행 `w-9` → 완료 `w-11` / 미진행 `w-9`. opacity 완료 1.0 / 미진행 0.6.

### 7-2. 좌측 ActivitySidebar (flow-integrator)

기존:
1. **현재 단계 아이덴티티** (헤더 박스: stage color + 이름 + 목표문 + 진행률)
2. **"팀이 할 일" 3문장** (단계 고정)
3. **활동 리스트** (번호 + 라벨 + 상태 아이콘, viewing은 `activity-glow`)
4. **탐색 모드 배너** (팀원이 방장과 다른 활동 볼 때만)
5. **선택된 활동 개념 안내** (`ACTIVITY_INFO` body + example)
6. **단계 분석 버튼** (전체 활동 완료 시에만)
7. **범례** (가드레일·평가 먼저 아이콘)

**v1.1 신규 (pedagogy-auditor 반영)**:
- **8. `STAGE_GUIDE.teamTasks` 동적 교체** (필수): 현재 단계 단위 고정 3문장 → `viewingActivity` 기준으로 1~2 항목 **동적 교체**. 예 `T-2-1` viewing 시 "각자 강점을 확인하고 역할을 나눠요"로 갱신. (실제는 `STAGE_GUIDE[stage].teamTasks` 를 `ACTIVITY_TASKS[activity]` 매핑이 있으면 덮어쓰는 머지 로직).
- **9. `ACTIVITY_INFO` 필드 2개 추가** (필수):
  - `whyNow`: "왜 지금 이 활동인가" — 직전 활동 산출물과의 연결 (예 Ds-1-1: "A-2-3 학습자 프로필을 평가 기준에 반영할 때입니다").
  - `warningRecoveryHint`: 건너뜀 상태일 때 **왜·언제 돌아와야 하는지** 문장. warning 카드에만 노출.
- **10. 활동 카드 사이 미니 connector**: 활동 row 사이에 `h-6` 스트립 + 1줄 관계 라벨 ("비전 → 방향", "방향 → 역할 분담"). 산출물 흐름이 있는 경우에만 표시 (실제는 `flex-col` 내부 `divide-y` 대신 커스텀 세로 connector 컴포넌트).

- **12. 상태 라벨 교육적 문구 교체** (필수): 기존 "건너뜀" → **"미완성 — 복귀 필요"**, 기존 "재검토 중" → **"품질 개선 중"** (§1-3 규약).
- **13. viewing 항목 강조**: row height +4px + `border-left 4px stage.bg` stripe로 "이게 지금 중심" 표시 (v1 유지).

## 8. 구현 시 주의 (area owner 공통)

- **토큰 우선**: 새로 만드는 요소는 `var(--primary)` 등 CSS 변수 또는 STAGE_COLOR 모듈 참조. 신규 hex 직접 삽입 금지.
- **기존 애니메이션 유지**: `morph-shape`, `activity-glow`, `stage-bounce`, `chevron-flow`, `corner-wrap-*` 는 T-CID 브랜드 모션. 추가·변경하지 말고 **위치·크기만 조정**.

- **표현·구현 차이 부연**: 문서에 비유적 표현이 있으면 괄호로 구현 메커니즘 명시 (이 문서 곳곳에 적용된 패턴).

## 10. 후속 데이터·스키마 이슈 (UI 스펙 범위 밖)

아래 항목은 UI만으로 해결 불가, 데이터·타입 작업이 선행되어야 함. area owner들은 **임시 하드코딩으로 v1.1 구현**하되, 후속 태스크로 기록:

1. **`ACTIVITY_META.downstream` 필드 신설**: §7-3 "forward-link 문구" 구현에 필요. 각 활동이 어떤 후속 활동의 입력이 되는지 매핑. 현재 채팅 프롬프트에만 존재하는 관계를 타입화.
2. **`ACTIVITY_META.whyNow` / `warningRecoveryHint`**: §7-2 에서 ACTIVITY_INFO 확장 요구. 현재는 `ACTIVITY_INFO`가 컴포넌트 내부 객체라 위치 이동 + 타입화 필요.
3. **`RequiredSectionsChecklist` 대상 확장**: T-1-1, A-2-3, Ds-1-1에 `requiredSections` 정의 추가. 스키마 마이그레이션·grandfather 처리 필요.
4. **이전 산출물 관계 타입 (`guardrail/basis/prev_step/related`)**: §7-3 관계 라벨 렌더에 필요. 현재는 previousArtifacts가 코드 기반 추론이므로, 명시적 관계 맵 `ACTIVITY_RELATION_MAP` 을 타입으로 정의.

## 11. 라이브 진행 인디케이터 (v1.2 신규)

**목적**: 3영역 모두 "지금 팀이 어느 단계·어느 활동에 있는가"를 정지 화면이 아니라 **살아있는 느낌**으로 전달. 과한 attention-grab 애니는 피로감을 주므로 1) 현재 지점은 잔잔한 pulse, 2) 지나온 단계는 순차 shimmer wave 두 축으로 분리한다.

### 11-0. as-built 정본 (globals.css 기 반영)

flow-integrator·data-architect 협업으로 아래 3 keyframe이 이미 병합됨. **본 스펙의 정본 값**으로 고정하며 area owner는 이 클래스명을 그대로 쓴다.

| 클래스 | duration / easing / repeat | 용도 | 현재 연결 파일 |
|---|---|---|---|
| `.live-dot-pulse` | `1.4s ease-in-out infinite` | 현재 활성 지점 맥박 (dot·chip·ring) | `page.tsx` collapsed Sidebar strip(L715) |
| `.stage-wave-bob` | `2s ease-in-out infinite` | 5단계 브레드크럼 파도-bob — translateY(-5px)+scale(1.2)+brightness·saturate+box-shadow sparkle 복합. `animation-delay`로 스태거 | `page.tsx` collapsed StageBar breadcrumb 전 5단계(L802, delay=`i*0.22s`), 현재 단계는 크기만 `w-2.5 h-2.5`로 강조 |
| `.stage-current-halo` | `1.8s ease-out infinite` | 확장 StageBar 현재 노드 halo glow (stage-bounce 병행) | **미연결** — StageBar 확장 모드 현재 노드에 추가 필요 |
| `.artifact-strip-pulse` | `1.2s ease-in-out infinite` | 산출물 업데이트 알림 — 유지 (용도 구분) | ArtifactPanel `ArtifactPanel.tsx:971`, `:1481` |

**구분 원칙**: `artifact-strip-pulse` = **이벤트성 알림**(새 산출물 도착, 섹션 업데이트). `live-dot-pulse` = **상태 지속 신호**(계속 현재인 동안 계속 맥박). 같은 dot에 두 클래스를 동시에 얹지 말 것 — 이벤트 발생 시 artifact-strip-pulse 우선, 종료 후 live-dot-pulse로 복귀.

### 11-1. 공통 토큰

globals.css에 이미 하드코딩된 duration 값을 **후속 PR에서 CSS 변수화** 권장. 현재는 하드코딩 유지하되, 토큰 제안만 §10에 보류:

```css
:root {
  --live-pulse-duration: 1.4s;    /* live-dot-pulse */
  --live-wave-duration: 2s;        /* stage-wave-bob */
  --live-halo-duration: 1.8s;      /* stage-current-halo */
  --live-wave-stagger: 0.22s;      /* 단계 간 delay 간격 */
}
```

area owner는 **값 변경이 아니라 이름 참조**로만 리팩터링. 현재 구현은 as-built 값과 일치하므로 교체 시 시각적 변화 0.

### 11-2. Pulse dot — 3영역 적용 규칙

사용자가 "지금 이 지점이 **실시간**" 임을 읽는 마이크로 시그널. dot 크기는 **영역 위계**에 비례(작을수록 보조, 클수록 주역).

| 영역 | 위치 | 크기 | 색상 소스 | 상태 조건 | 현재 |
|---|---|---|---|---|---|
| Sidebar(접힘) | 세로 strip 상단 현재 활동 dot | `w-2 h-2` | `STAGE_COLOR[currentStage].hex` | 항상 맥박 (현재 = viewing) | 반영 완료 `page.tsx:715` |
| StageBar(접힘) 브레드크럼 | 5단계 dot 전체 (현재는 크기만 1.67배) | 현재 `w-2.5 h-2.5` / 나머지 `w-1.5 h-1.5` | `STAGE_COLOR[stage].hex` (각 단계 고유색) | 5단계 모두 `.stage-wave-bob` + `animation-delay: i*0.22s` — 현재 구분은 크기로만 | 반영 완료 `page.tsx:802` |
| StageBar(확장) | 현재 단계 노드 주변 halo | `w-14 h-14 ring` | `STAGE_COLOR[currentStage].pulse` rgba | 현재 노드만 (stage-bounce와 병행) | **대기** — StageBar.tsx에 `.stage-current-halo` 추가 필요 |
| ArtifactPanel(접힘) | 세로 strip 상단 status dot | `w-2.5 h-2.5` (파일 아이콘 부착) | `statusDotColor` + `color: statusDotColor` currentColor 위임 | 3분기: `justUpdated → artifact-strip-pulse` / `isLiveViewing && 산출물 있음 && !confirmed → live-dot-pulse` / 그 외 정지 | 반영 완료 `ArtifactPanel.tsx:1475~1502` |

**참고**: 상단바 팀원 아바타 스택은 Crown 아이콘이 이미 host 식별을 수행하므로 **pulse 미적용** — 정보 밀도·겹침 위험 회피. §11-6 확장 후보 참조.

**ArtifactPanel 분기 로직 (as-built — `ArtifactPanel.tsx:1475~1502`)**:
```tsx
const isLiveViewing = viewingActivity === currentActivity
const isConfirmed = firestoreArtifact?.status === 'confirmed'
const pulseClass = justUpdated
  ? 'artifact-strip-pulse'                              // 이벤트성 알림 (우선)
  : isLiveViewing && firestoreArtifact && !isConfirmed
    ? 'live-dot-pulse'                                  // 상태 지속 신호
    : ''                                                // confirmed 또는 산출물 없음 → 정지
```
dot 색은 `statusDotColor`를, `live-dot-pulse` box-shadow가 `currentColor`를 쓰므로 `color: statusDotColor` 위임으로 halo 색 자동 일치. "확정된 산출물은 안정 상태"라는 의미를 맥박 부재로 표현 — 교수학 해석 §1-3 "팀 합의로 확정"과 정렬.

### 11-3. Sequential wave-bob (5단계 전체 파도 — as-built)

**의도**: T→A→Ds→DI→E 5단계 dot이 **왼쪽→오른쪽으로 파도처럼** translateY + scale + brightness sparkle로 반짝이며 "팀이 이 주기를 살아 움직이고 있다"는 전체 궤적감을 시각화.

**규칙 (as-built 정본)**:
- **모든 5단계**가 `.stage-wave-bob` 동일 keyframe을 공유. `animation-delay: i*0.22s`로 스태거 → 5단계 × 0.22s = 1.1s 앞뒤 지연 범위
- 현재 단계는 **크기로만 강조**(`w-2.5 h-2.5` vs `w-1.5 h-1.5`, 1.67배). 별도 pulse 클래스 배타 규칙 없음 — 당초 option C 초안(현재=pulse, 과거=wave 배타)은 실제 구현에서 "전 단계 공통 bob + 현재 크기 강조"로 통합됨
- 교수학 의도: wave가 과거/현재/미래를 동등하게 포함 → "이 주기는 살아 있고 계속 움직인다" (static/완료 구분보다 **연속적 흐름** 강조)
- keyframe 주기: 2s, 60~100% 구간이 정지(brightness 0.85·opacity 0.5)라 **bob은 40% 시간만 활성** — 인지 피로 최소화
- 커넥터(chevron `›`): **v1.2 범위 밖**, 정적 유지

**적용 범위 (v1.2)**:
1. StageBar 접힘 브레드크럼 — 반영 완료 (`page.tsx:795-816`)
2. StageBar 확장 모드 — **bob 미적용 고정**. 확장 노드는 morph-shape + stage-bounce + `stage-current-halo`(현재만) 3층 구조로만 운용. bob을 확장 노드에 얹지 않는다(transform 중첩 회피). flow-integrator 구현으로 확정 · StageBar.tsx:212에 GPU 레이어 분리 근거 주석 기록됨.
3. Sidebar·ArtifactPanel — **미적용**. 활동 단위는 wave 비유 과함, pulse dot만

**총 주기 감각**: 5단계 × 0.22s stagger = 1.1s 앞뒤 지연, keyframe 2s, 정지 구간(60~100%) 포함 전체 wave 사이클 약 2.3~2.5s 간격으로 되풀이.

### 11-4. Accessibility — prefers-reduced-motion

globals.css:345-347에 이미 정의됨(as-built):
```css
@media (prefers-reduced-motion: reduce) {
  .live-dot-pulse, .stage-wave-bob, .stage-current-halo, .artifact-strip-pulse { animation: none; }
}
```
- 모든 라이브 애니가 한 규칙에 묶여 있으므로 신규 keyframe 추가 시 **이 목록에 추가**를 필수로 간주 (§6 기존 접근성 원칙 확장)
- "정지 상태에서도 현재 지점은 읽혀야 한다" — reduced-motion일 때 현재 dot은 **`.ring-2 ring-offset-1`** 등 정적 강조로 fallback (area owner 재량, 단 색 대비는 WCAG AA 유지)
