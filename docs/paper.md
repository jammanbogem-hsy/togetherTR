# 협력적 수업설계 AI 에이전트 프로토타입 — 초등 편

> 본 문서는 협력적 수업설계 지원 AI 에이전트 프로토타입(이하 "에이전트")의
> **2장 2-2절(초등의 주요 기능 및 특징)** 과 **3장(AI 에이전트 프로토타입 활용 방법)** 에
> 해당하는 원고이다.

---

## 2-2. 초등의 주요 기능 및 특징

초등 프로토타입은 2-1절에서 기술한 공통 기능을 토대로,
초등 학교급의 **다교과 통합 수업 설계**와 **현장 적용 시간 제약**을 반영해
다음과 같은 차별적 기능과 특징을 포함하도록 설계되었다.
각 항목 끝의 *의도(Why)* 는 해당 기능을 포함시킨 설계상의 근거이다.

### 가. T-CID 5단계 비선형·순환 구조

본 에이전트는 T-CID 모형(이은상·김현진, 2020)의 5단계
— **T**(팀 준비) → **A**(분석) → **Ds**(설계) → **DI**(개발·실행) → **E**(평가)
— 를 **양방향 이동**과 **E→T 재진입**이 가능한 순환 구조로 구현하였다.

- 단계 간 이동은 일방향으로 강제되지 않으며, **이전 단계로의 회귀 사유**가 기록된다.
- 5단계 평가(E) 완료 시, 다음 수업 주기를 위한 **T 단계 재진입 제안 모달**이 노출된다.
- 완료 조건은 100% 충족이 아니라 **핵심 근거 3개 충족** 시 다음 단계로의 전진을 허용한다.

*의도(Why)*: 초등 수업설계는 학년 초·중·말 시기별로 학습자 분석 결과가 빠르게 변하고,
교사 협의 과정에서 비전·목표·평가가 상호 영향을 미치며 재조정되는 특성이 강하다.
따라서 단계 진행을 선형적으로 강제할 경우 실제 협력 설계 현장의 의사결정 흐름과 어긋난다.

### 나. 학습자·맥락 분석 활동(A-2-3) 신설

초등팀 협의 결과를 반영하여 **분석(A) 단계에 학습자·맥락 분석 활동(A-2-3)** 을
명시적으로 추가하였다. 다음 항목을 입력·검토하도록 설계되었다.

- **선수 지식 및 오개념**: 학년군 발달 단계상 흔히 나타나는 오개념 목록
- **수행 역량 제약**: 예) 디지털 도구 사용 시 **타자 속도**, 협력 도구 로그인 지원 등
- **환경 제약**: 학급당 학생 수, 1인 1기기 보급률, 차시 운영 제약, 강당·운동장 등 공간

A-2-3에서 도출된 학습자 프로필은 3단계 설계(Ds-1-3 학습 활동, Ds-2-2 스캐폴딩)에서
**가드레일(guardrail)** 로 자동 인용된다. 예컨대 스캐폴딩 설계 시
"타자 속도가 느린 학습자가 다수"라는 분석 결과가 있으면 에이전트가
**템플릿 제공·키워드 자동 완성·단어장 비계**를 우선 제안한다.

*의도(Why)*: 초등은 학년 간 인지·운동 기능 격차가 크고, 동일 학년 내에서도
타자 속도·기기 친숙도 편차가 크다. 학습자 분석 없이 설계된 디지털 기반 활동은
"느린 학생을 기다리느라 차시 운영이 무너진다"는 현장 피드백이 반복적으로 보고되었기에,
설계 시점에 학습자 변인을 명시적으로 외현화하도록 분석 활동을 분리·고정하였다.

### 다. 백워드 디자인(Backward Design) 적용

설계(Ds) 단계의 순서를 다음과 같이 재배열하여 **Wiggins & McTighe의 백워드 설계**
원리를 따른다.

```
Ds-1-1 평가 계획 수립    → "어떻게 도달을 증명할 것인가"
Ds-1-2 문제 상황 개발    → "어떤 실생활 맥락에 몰입시킬 것인가"
Ds-1-3 학습 활동 설계    → "WHERETO 기반 차시 여정"
Ds-2-1 지원 도구 설계    → "AI·에듀테크 매칭"
Ds-2-2 스캐폴딩 설계     → "Tailor(맞춤형) + Fading(점진적 제거)"
```

특히 Ds-1-3 학습 활동은 **WHERETO 원리**(W-H-E-R-E-T-O)에 따라
*동기유발(Hook) → 탐구(Equip) → 재고(Rethink) → 맞춤화(Tailor) → 조직(Organize)* 의
교수 전략 흐름이 충족되었는지 에이전트가 기계적으로 점검한다.

*의도(Why)*: 초등 PBL 수업에서 "활동은 풍부한데 무엇을 평가할지 불분명"한 사례가 빈번하다.
평가 계획을 먼저 확정한 뒤 문제 상황과 활동을 역설계함으로써,
**목표 ↔ 평가 ↔ 활동의 정합성(alignment)** 을 구조적으로 보장한다.

### 라. 통합 교과 융합 지원 — 성취기준 연결맵

초등은 동일 주제를 여러 교과에 걸쳐 다루는 **통합 수업·프로젝트 수업**이 일반화되어 있다.
이에 따라 다음 기능을 포함한다.

- **2022 개정 교육과정 성취기준 데이터베이스 3,134개** 내장
- 학년군별 가중치(동일 학년군 +0.2, 인접 학년군 +0.1) 적용한 **하이브리드 검색**
  (TF-IDF 키워드 매칭 + 의미 임베딩)
- 선정된 성취기준 간 공유 키워드 기반 **융합 지식 그래프**를 자동 생성하여,
  교과 간 연결 고리를 마인드맵으로 시각화
- 중복 내용·기능 요소를 에이전트가 탐지해 **통합 가능 항목**을 제안
  (예: 국어 "요약하기" ↔ 사회 "정보 파악" → 단일 통합 기능으로 묶기)

*의도(Why)*: 초등 교사가 다교과 융합 수업을 설계할 때 가장 큰 부담은
"각 교과 성취기준을 일일이 찾아 연결하는 작업"이다.
연결맵 시각화는 협의 과정에서 누구나 동일한 그림을 보며 토의할 수 있는
**외현화 도구**로 기능한다.

### 마. 5가지 행위주체 명시화

설계 절차의 각 활동 단계마다 **누가 그 행위를 수행하는가**를 다음 5가지로 명시한다.

| 표기 | 행위주체 | 의미 |
|------|---------|------|
| 👤 | 개인교사 | 교사 한 명이 단독으로 판단·기록 |
| 👥 | 교사팀 | 팀 내 협의·합의 |
| 👤🤖 | 개인 + AI | 개별 교사와 AI의 상호작용 |
| 👥🤖 | 팀 + AI | 팀 협의에 AI가 보조 |
| 🤖 | AI 단독 | AI만의 자동 처리 (안내·점검·기록) |

각 활동 단계의 표 첫 열에 위 아이콘이 부착되어 있어,
**AI 개입 경계**가 한눈에 드러난다.

*의도(Why)*: "AI가 수업을 대신 설계하는 도구"라는 오해를 방지하기 위함이다.
초등팀 협의에서 가장 강하게 요구된 사항이 *"AI는 교사를 대체하지 않고
교사의 의사결정을 가시화하고 점검하는 역할에 머물러야 한다"* 였다.

### 바. 10종 활동 유형 태깅

모든 절차 단위 활동에 다음 10종의 활동 유형 중 하나가 태깅된다.

```
📋 제시 · 🔎 탐색 · 💡 생성 · 📊 시각화 · 🗣️ 공유 및 협의
⚙️ 조정 · ✅ 점검 · 🪞 성찰 · 🤔 판단 · 💾 기록
```

활동 유형은 단순 분류를 넘어 **에이전트의 응답 형식**과도 연동된다.
예컨대 `🗣️ 공유 및 협의` 단계에서는 AI가 결론을 내리지 않고
**팀 자유 토론 모드**로 진입하는 신호(`[TEAM_DISCUSSION_READY]`)를 출력한다.

*의도(Why)*: 초등 수업설계는 "어떤 종류의 사고가 일어나는지"에 따라
AI의 적정 개입 강도가 달라야 한다. 활동 유형 메타데이터는
AI 응답 톤·길이·개입 강도를 자동으로 조절하는 스위치로 기능한다.

### 사. 팀 자유 토론 모드

AI 퍼실리테이션 중 토의가 필요한 시점이 감지되면, 에이전트는 자동으로
다음 흐름을 트리거한다.

```
AI 응답 내 [TEAM_DISCUSSION_READY: 주제] 신호 출력
    → 화면에 "팀 자유 토론을 시작하시겠습니까?" 카드 노출
    → 호스트(주관 교사) 승낙 시 AI는 대기 모드 진입
    → 교사팀이 자유 메시지 교환 (Firestore 실시간 동기화)
    → 호스트가 "토론 종료 → AI 분석" 클릭
    → AI가 ① 합의된 내용 ② 미결 사항 ③ 다음 행동 추천 3섹션으로 정리
```

*의도(Why)*: 선행 연구(이동국 외, 2025)에서 AI 에이전트의 가장 큰 약점으로
**과도한 질문 피로도**와 **AI가 교사 간 대화를 끊는 현상**이 보고되었다.
"AI를 잠시 대기시키는 명시적 모드"가 있어야 협력적 사고가 보호된다.

### 아. 신호 토큰 기반 AI ↔ 상태 결합

본 에이전트는 자연어 응답 안에 다음 **신호 토큰**을 임베드함으로써
AI의 의도와 시스템 상태 전이를 동기화한다.

| 신호 | 효과 |
|------|------|
| `[ACTIVITY_ADVANCE: 코드]` | 현재 활동 완료 처리, 다음 활동으로 이동 |
| `[ACTIVITY_RETURN: 코드]` | 이전 활동으로 회귀 (active_return 상태) |
| `[ARTIFACT_UPDATE: 섹션=내용]` | 산출물 패널의 해당 섹션을 실시간 갱신 |
| `[TEAM_DISCUSSION_READY: 주제]` | 팀 자유 토론 배너 노출 |

이 구조는 AI가 *"다음 단계로 이동하겠습니다"* 라고 자연어로만 말하고
실제 상태는 변경되지 않는 **표현·구현 불일치** 문제를 차단한다.

*의도(Why)*: 초등 교사 사용자 검증에서 가장 빈번한 혼란 지점이
"AI가 진행했다고 말했는데 화면이 바뀌지 않는다"였다.
토큰 기반 결합은 자연어 표현과 시스템 상태 사이의 일관성을 보장한다.

### 자. 활동별 채팅·산출물 분리

채팅 메시지와 산출물(artifact)은 **활동 코드(activityCode) 기준으로 분리 저장**된다.

```
projects/{프로젝트ID}/conversations/{활동코드}/messages
projects/{프로젝트ID}/artifacts/{활동코드}
```

이로써 T-1-1 비전 설정 활동의 채팅 히스토리는 A-1-2 주제 선정 활동으로
이동했을 때 노출되지 않으며, 각 활동의 **대화 맥락이 독립적으로 보존**된다.
이전 활동으로 돌아가면 그 시점의 채팅·산출물이 그대로 복원된다.

*의도(Why)*: 초등 협력 설계는 활동 단위로 사고가 끊기고 이어진다.
모든 메시지가 하나의 채팅창에 섞이면 "지금 우리가 어느 활동을 하고 있는지"가
빠르게 흐려진다는 현장 피드백이 있었다.

### 차. 산출물 패널 — AI 초안과 교사 확정의 분리

화면 우측의 **산출물 패널(ArtifactPanel)** 은 두 영역으로 구분된다.

- **AI 초안**: 에이전트가 제안한 내용 (편집 가능, 미확정 상태)
- **교사 확정**: 팀이 검토·승인하여 종합 리포트에 영구 반영된 내용

교사가 명시적으로 *"확정"* 버튼을 누르기 전까지는 AI 제안이 리포트에
자동 저장되지 않는다.

*의도(Why)*: 협력적 수업설계 5원리 중 **외현화(externalization)** 와
**조정(coordination)** 의 구현이다. AI의 생성물이 자동 확정되면
교사의 비판적 검토 과정이 생략되는 위험이 있다.

### 카. 실전 운영 약식 모드 (T-2 옵션화)

초등 현장에서는 **단기 연수 1일** 안에 협력 설계를 완료해야 하는
운영 제약이 빈번하다. 이를 위해 1단계의 **역할 분담(T-2-1)·팀 규칙(T-2-2)·
팀 일정(T-2-3)** 은 호스트의 설정으로 약식 진행 또는 건너뛰기가 허용된다.
단, 후속 단계에서 충돌이 발견되면 *"T-2로 돌아가시겠습니까?"* 안내가 자동 노출된다.

*의도(Why)*: 표준 절차를 고정하면 학교 현장의 시간 제약을 수용하지 못해
도구 자체가 사용되지 않는다. 유연성을 제공하되,
중요한 누락에 대한 **자동 환기(reminder)** 를 함께 보장한다.

### 타. 종합 리포트 자동 생성

설계가 단계별로 진행됨에 따라 종합 리포트가 **자동 누적 작성**된다.
최종적으로 다음 5부 구성으로 출력 가능하다(Markdown / PDF).

```
1. 팀 준비    : 비전 · 설계 방향 · 역할 · 규칙 · 일정
2. 분석       : 주제 선정 기준 · 최종 주제 · 성취기준 분석 · 통합 목표 · 학습자/맥락 분석
3. 설계       : 평가 계획 · 문제 상황 · 학습 활동(차시 여정) · 지원 도구 · 스캐폴딩 명세
4. 개발·실행  : 개발 자료 목록 · 수업 기록 (에피소드)
5. 평가       : 수업 성찰 · 설계 과정 성찰
```

*의도(Why)*: 초등 교사가 협력 설계 결과를 **연구회·동학년 협의·연수 보고**에
재사용할 수 있는 형태로 즉시 제공하는 것이 핵심이다.

## 3. AI 에이전트 프로토타입 활용 방법

### 3-1. 접속 링크

> 프로토타입 접속 URL은 **추후 공개 예정**이다. 정식 배포 시점에 본 절에 기재한다.
>
> - 깃허브 저장소 주소 공개 여부는 추후 논의를 통해 결정한다.
> - 시범 사용을 희망하는 연구진은 본 논문 교신저자에게 별도 안내를 요청할 수 있다.

### 3-2. 활용 방법

본 에이전트는 다음 단계를 따라 사용한다. 각 단계는 화면 안내 순서와 일치한다.

#### (1) 워크스페이스 생성 및 팀원 초대

1. 로그인 후 *"새 워크스페이스 만들기"* 를 선택한다. 학교명·팀명을 입력한다.
2. 워크스페이스 생성자는 자동으로 **Owner** 권한을 가진다.
3. 이메일 초대 또는 초대 링크를 통해 팀원을 추가한다. 팀원의 권한은
   **Editor**(설계 편집·AI 대화 가능) 또는 **Viewer**(열람·코멘트만 가능)로 지정한다.

#### (2) 프로젝트 생성 및 학습자 맥락 입력

1. 워크스페이스 내에서 *"새 프로젝트"* 를 클릭하여 학년·교과·단원명을 입력한다.
2. **학습자 맥락**(학생 수, 디지털 리터러시, 직전 단원, 학급 특성)을 입력하면
   이후 AI의 모든 응답에 자동 반영된다.
3. 프로젝트가 생성되면 좌측 사이드바에 **T → A → Ds → DI → E** 5단계 진입 메뉴가 나타난다.

#### (3) T 단계(팀 준비) 진행

1. **T-1-1 비전 설정**: 각 교사가 키워드를 입력하면 AI가 3가지 융합 비전안(A·B·C)을 제안한다.
   팀이 협의하여 최종 비전 1문장을 확정한다.
2. **T-1-2 설계 방향 수립**: 비전을 토대로 교수학습 방향(예: PBL, 블렌디드 등)을 합의한다.
   AI는 비전과 설계 방향의 정합성을 점검한다.
3. **T-2-1~3 역할 분담·팀 규칙·팀 일정**: 단기 연수 상황에서는 호스트 설정으로
   약식 진행 가능하다.
4. 채팅창 응답에 `[ACTIVITY_ADVANCE]` 신호가 포함되면 자동으로 다음 활동으로 이동한다.

#### (4) A 단계(분석) 진행

1. **A-1 주제 선정**: 주제 선정 기준 → 후보 군집화 → 최종 주제 확정 순으로 진행한다.
2. **A-2-1 성취기준 분석**: 교과·키워드 입력 → AI가 2022 개정 교육과정에서
   관련 성취기준을 추출 → 내용 요소(지식)·기능 요소(과정)로 분해 → 교과 간 연결맵 시각화.
3. **A-2-2 통합 수업 목표**: 분해된 성취기준을 결합해 **단일 통합 목표 문장**으로 수립한다.
4. **A-2-3 학습자·맥락 분석**: 선수 지식, 오개념, 운동 기능(타자 속도 등), 환경 제약을 입력한다.
   여기서 도출된 프로필은 이후 Ds 단계 설계 시 가드레일로 자동 인용된다.

#### (5) Ds 단계(설계) 진행

1. **Ds-1-1 평가 계획**(우선) → **Ds-1-2 문제 상황** → **Ds-1-3 학습 활동(WHERETO 차시 여정)**.
2. **Ds-2-1 지원 도구**: AI·에듀테크 도구를 차시별로 매칭한다. 학교 인프라(웨일 스페이스 등)에
   따라 추천이 조정된다.
3. **Ds-2-2 스캐폴딩**: 학습자 프로필에 기반해 차시별 비계(템플릿, 힌트, 단어장 등)를 설계한다.
   페이딩(Fading) 전략을 명시적으로 검토한다.

#### (6) DI 단계(개발 · 실행) 진행

1. **DI-1-1 개발 자료 목록**: 설계안에서 누락된 자료를 AI가 자동 점검하여 제안한다.
2. **DI-2-1 수업 기록**: 실행 후 에피소드(성공/장애/예상외 반응)를 자유 입력한다.
   AI는 입력 내용을 자동으로 분류·시각화한다.

#### (7) E 단계(평가) 및 다음 주기

1. **E 단계 수업 성찰·설계 과정 성찰** 활동을 완료한다.
2. AI가 *"다음 주기 T 단계로 진입하시겠습니까?"* 모달을 제시한다.
   진입을 선택하면 E 단계에서 도출된 개선사항이 새 주기 T-1-2 설계 방향에 자동 반영된다.

#### (8) 비동기 협업과 출력

- 각 섹션에 **코멘트 스레드**를 부착할 수 있다. 코멘트 등록 시 팀원에게 인앱 알림이 전송된다.
- *"리포트 출력"* 버튼을 누르면 종합 리포트가 Markdown 또는 PDF로 즉시 생성된다.
- 단계별로 임시 출력도 가능하다(예: A 단계까지만 출력하여 동학년 협의 자료로 사용).

#### (9) 단계 이동 자유와 회귀

- 5단계 진행 중 언제든 이전 단계로 돌아갈 수 있다. 이때 회귀 사유를 짧게 입력해야 하며,
  이 사유는 활동 로그(activity_logs)에 남아 추후 설계 회고에 활용된다.
- 회귀된 활동은 **active_return** 상태로 표시되어, 처음 진행 때와 시각적으로 구분된다.

### 3-3. 유의 사항

#### 가. 보안 및 계정 관리

- **공용 PC 사용 금지**: 학교 공용 PC에서 로그인한 경우 반드시 세션을 명시적으로 종료한다.
- **이메일 인증 기반 초대 링크**는 유효 기간이 설정되어 있으며, 만료 후에는 재발급해야 한다.
- 호스트 설정의 **API 키**(LLM 키)는 평문으로 저장되지 않으며, 마지막 4자리만 노출된다.
  키를 교체할 경우 즉시 이전 키를 폐기한다.
- 깃허브 저장소를 사용하는 개발자는 **개인 액세스 토큰(PAT)을 코드·remote URL에 포함시키지 않는다**.
  토큰은 환경 변수 또는 OS 키체인으로 분리 보관한다.

#### 나. 개인정보 보호

- **학생 실명을 입력하지 않는다**. 분석·기록 시 *"학생 A, 학생 B"* 또는 *"4학년 1반 ○○○"* 등
  비식별 표기를 사용한다.
- **학교 식별 정보**(주소, 학교명 약칭 등)는 활동 기록에 포함시키지 않는다.
  종합 리포트의 표지에 학교명을 적더라도 외부 공유 전에는 마스킹한다.
- 학습자 분석(A-2-3)에 학생의 **장애·가정 환경·민감 정보**를 입력하지 않는다.
  필요한 경우 *"디지털 도구 사용 어려움 있음"* 등의 **기능적 기술**로 대체한다.
- 수업 기록(DI-2-1) 에피소드에 학생의 **부정적 행동을 식별 가능한 형태로 기재하지 않는다**.

#### 다. AI 응답의 한계와 검증 책임

- AI가 제안한 성취기준 매칭·학습 활동·평가 루브릭은 **초안**이다. 최종 채택 책임은 교사팀에 있다.
- AI는 2022 개정 교육과정 데이터베이스 기반으로 응답하나, 일부 교과의 미세 개정 사항이
  반영되지 않았을 수 있다. **정확한 성취기준 표기는 NCIC 원문**과 대조한다.
- 시각화 자료(연결맵, 클러스터 등)는 통계적 유사도에 기반한 시각화로,
  교과 본질적 연결성과는 다를 수 있다.

#### 라. 데이터 보존 및 외부 전송

- 입력된 모든 텍스트는 LLM 응답 생성을 위해 **외부 LLM API(예: Anthropic/OpenAI)** 로 전송된다.
  민감 정보 입력을 자제한다.
- 프로젝트 데이터는 Firebase Firestore에 저장되며, 호스트 설정에 따라
  보존 기간을 지정할 수 있다.
- 프로젝트 종료 후에는 **활동 로그·채팅 메시지·산출물**의 영구 삭제 또는 익명화 처리를 권장한다.

#### 마. 저작권

- 종합 리포트의 학습 자료·문제 상황 등은 교사팀의 창작물로 간주된다.
  AI의 제안을 그대로 인용한 부분이 있다면 보고서 말미에 *"AI 제안 활용 비율 / 수정 정도"* 를
  간단히 명시할 것을 권장한다.
