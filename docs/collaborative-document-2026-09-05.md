# 문서형 공동 편집 1차 적용

## 범위
- 수업설계 방향(T-2) 공동 편집창의 추가 본문만 Tiptap + Yjs로 전환.
- 기존 상단 표와 나머지 공동 편집창은 기존 편집 방식 유지.
- Enter/Backspace 문단 분리·합치기, 제목/인용, 문단 위·아래 이동, 실행 취소.
- 문서 컴포넌트와 동기화 어댑터를 분리하여 이후 다른 편집창에서 재사용 가능.

## 저장
- 프로젝트의 lessonDesignDirectionDocument에 Yjs 상태와 원본 블록 백업 저장.
- 250ms 디바운스 후 Firestore transaction에서 원격 상태와 병합.
- 같은 트랜잭션에서 기존 workspace.blocks로 본문을 투영하여 산출물 호환 유지.
- 기존 표 편집 저장도 transaction으로 바꾸며 CRDT 본문을 덮어쓰지 않음.
- 저장 중 상태/실패/재시도 표시. 닫기·산출물 전송은 본문 저장 완료 대기.
- 브라우저 복구용 상태는 사용자·프로젝트·주기·편집 인스턴스별 localStorage에 저장.
- 문서 상태 350,000 base64 문자 상한. 제한 도달 시 저장 실패를 표시하며 내용은 삭제하지 않음.

## 검증
- 독립 Y.Doc 2개의 동일 위치 입력, 삭제+입력, 순서 변경된 업데이트 전달, 재전송 멱등성 테스트.
- 제목·인용·체크리스트 마커·표 내용의 레거시 변환 테스트.
- 실제 브라우저: 입력, 자동 저장, 닫기 후 재열기, Enter 문단 분리, Backspace 합치기 확인.
- 검증 프로젝트: http://localhost:3000/projects/PkrHVB0ZICEYGQDts1kr
- 테스트 중 빈 표 구조가 없는 프로젝트의 산출물 전송 오류를 발견하여 기본 구조 정규화 추가.
- 수정 후 실제 브라우저에서 산출물 v1 생성 성공. 기존 T12Renderer의 추가 본문 미표시를 수정하고 본문 렌더·HTML 이스케이프 테스트 추가.

## 남은 검증/제한
- 서로 다른 계정 2명의 실제 동시 입력은 미검증. 브라우저 두 번째 창 연결에 타임아웃 발생.
- 네트워크 장애·오프라인 복구는 구현했으나 실제 장애 주입 E2E는 미완료.
- 상단 표의 동일 셀 동시 타이핑은 CRDT가 아님.
- 문단 순서 이동과 해당 문단 동시 입력의 의미적 충돌은 별도 검증 필요.
- 다른 활동 편집창 전환은 후속 작업이며 전체 완료가 아님.
- 실시간 상대방 커서/선택 영역 표시는 이번 범위에 없음.

설계 참고: [Yjs updates](https://docs.yjs.dev/api/document-updates), [Tiptap Collaboration](https://tiptap.dev/docs/editor/extensions/functionality/collaboration).
