## 검증 방법

1. 로그인된 실제 브라우저에서 교사 수와 페르소나를 입력하고 AI 확장 → 검토 → 프로젝트 생성 → 실행 버튼을 1회 사용.
2. 실행 화면과 실제 저장 프로젝트 화면을 확인하여 생성 대화, 참가자, 진행 및 산출물 확인.
3. 실제 `runLiveMultiAgentDemo`, 입력·출력 파서 및 프롬프트를 실행하는 동작 테스트 추가. 모델 HTTP 응답과 Firestore만 mock으로 대체한다.
4. TypeScript·ESLint 검사. 실행 흐름 및 활동 절차·산출물 검증 코드 대조.

실제 모델 대화의 질은 mock 테스트로 증명하지 않는다. 2·4·5명 전체 실 AI 실행은 하지 않았으며, 그 인원수는 동작 테스트로만 확인했다. 모든 응답의 교육적 정확성이나 교육과정 원문 정합성을 인증한 것은 아니다.

## 확인된 작동

- 설정 확장이 입력한 이름·경력·전문 관점을 유지했다.
- 총괄 제시가 먼저 생성되고, 교사마다 분리된 모델 요청으로 제안·응답이 생성됐다. 미리 작성한 대본 재생이 아니다.
- 1차 제안에는 동료 제안이 주입되지 않고, 2차 응답에는 전체 1차 제안이 전달된다.
- 실제 T-3에서 김하늘은 데이터/시연 기술 초안, 이도윤은 역사 서사/근거 유도 질문, 박서연은 접근성 기록지를 맡자는 상호의존적 제안을 했다.
- 실제 동료 이름을 부르고 제안에 동의·우려·절충안을 붙이는 발언을 확인했다.
- 활동별 대화와 산출물이 프로젝트에 저장되고, 이전 산출물 상세 보기에서 열렸다.

## 우선 수정 사항

### P1. 활동별 절차가 약해 논의가 다른 활동의 내용으로 흐른다

실제 관찰:

- T-2(수업설계 방향)는 '~하려면 ~해야 한다' 원칙·번호·멈춤 조건이 필요하다. 저장 결과는 차시 구조, 합성 데이터 분리, 접근성 및 평가 지표 중심이며 멈춤 조건은 없었다.
- T-4(팀 규칙)에서 교사팀의 소통·갈등 조정 대신 학생의 1분 발언, 수업 내 시간표, 데이터 표기 규칙이 중심이 됐다.
- A-1(주제 선정 기준)과 A-2(주제 선정)의 총괄 제시는 후보·선정 기준보다 NA/0 비율, 시연 준비, 제출물 채점으로 이어졌다.
- A-3(교과 내용 분석)에서도 다시 동일한 데이터 비율·기록지 축약 논의가 반복됐다.
- DI-2(수업 실행·기록)는 관찰 사실·증거 검토보다 NA/0 배치와 시연·지원 절차 제안을 반복했다. E-1(수업 성찰)의 총괄은 '수업 실행 전 독립적으로 검토'할 쟁점으로 CSV/PDF 배포 방식을 제시했다. 수업 실행 증거 → 해석 → 수정으로 전환되지 않았다.

원인: `src/lib/demo/engine/prompts.ts`의 `ACTIVITY_FOCUS` 한 문장과 섹션명만 사용하고, `src/lib/prompts/system.ts`의 상세 활동 절차와 완수 기준을 사용하지 않는다. 모든 활동에 동일한 8턴 구조를 적용한다.

권고: 기존 활동 절차를 공용 정의로 추출해 세부 활동 상태·필수 질문·종료 조건을 실행 엔진과 공유한다. 현재 활동의 목적을 벗어났으면 총괄이 재초점화하도록 한다.

### P1. 추가 확인 요청·미합의 상태에도 자동 확정한다

T-5 종합의 실제 발언: '여러분의 확정 답변을 받아 구체 날짜로 역산한 팀 일정 표…를 만들어 제출하겠습니다.' 그러나 그 뒤 교사 답변 없이 활동 저장 완료 → A-1로 이동했다.

`src/lib/demo/engine/run.ts:409`는 종합 출력 후 곧바로 `status: 'confirmed'`, `confirmedBy: ownerUid`로 저장한다. 별도 합의 상태, 추가 토론 루프, 실제 소유자 승인이 없다. 미해결 질문을 보존하는 것과 답을 받은 뒤 확정하는 것은 다르다.

완료 프로젝트의 E-2 산출물에는 실제 사람의 승인 조작을 하지 않았는데 **'내가 확정함 · 9. 5. 오전 11:17'**이 표시됐다.

권고: `needsDiscussion`/`proposed`/`agreed` 상태와 교사별 동의 여부를 분리한다. 데모 자동 승인 주체를 실제 사람 UID의 승인처럼 기록하지 않는다.

### P1. 동료 발언을 잘못 귀속해 가짜 반론·합의를 만든다

실제 T-1에서 김하늘은 박서연이 '측정 원리 실험과 통계 분석을 모두 깊게 다루자'고 제안한 것처럼 반론했다. 박서연의 실제 제안은 작업량·인지부하 경감이었다. 종합에서도 이도윤에게 실제로 말하지 않은 반대 입장을 귀속했다.

T-5 종합은 박서연을 전원 파일럿 주장 쪽으로 분류했다가 같은 발언 안에서 '전교사 파일럿 전면 시행에 반대하는 조건을 유지'한다고 정리했다.

원인 후보: `prompts.ts:188`은 매 응답에 반론·긴장을 의무화하지만, 인용 대상 메시지 ID·정확한 근거·발화자 일치 검증은 없다. 출력 파서는 동료 이름 포함 여부만 확인한다(`types.ts:592`).

권고: 응답 대상 메시지 ID와 원문 근거를 구조화하고, 실제 이견이 없으면 억지 반론 없이 동의·보완을 허용한다. 종합 후 당사자 검토 턴을 둔다.

### P1. 산출물은 섹션명·문자 수만 통과하면 확정된다

`types.ts:609` 이후 검증은 필수 섹션의 정확한 이름·중복·문자 수를 확인한다. 실제 필수 표의 열, 원칙과 멈춤 조건, 일정의 순서, 평가-목표 연결은 검증하지 않는다. 생성 값은 문자열이므로 앱의 활동별 구조화 워크스페이스를 채우는지까지 보장하지 않는다.

실제 T-2 산출물은 상세 보기에서 정상 렌더링됐지만 활동 완수 요건이 빠졌다. 추가한 재현 테스트에서도 원칙·멈춤 조건이 없다고 명시한 텍스트가 산출물 파서를 통과한다.

완료 후 Ds-1 평가 계획도 확인했다. 목표·체크리스트·운영 규칙은 있으나 '확인 지점·평가 요소·방법·시점·주체'의 대응 표가 아니라 긴 서술/목록이다. 근거의 관련성은 선택적 보너스 항목으로 밀려나 핵심 학습목표와 평가의 연결도 재검토가 필요하다.

권고: 활동별 구조화 산출물 스키마·필수 행/열·내용 완수 조건을 검증하고, 미충족 시 교사에게 필요한 기여를 요청한 뒤 재생성한다.

### P1. 실행 중 프로젝트 화면을 열면 일반 채팅 흐름이 충돌한다

실행 화면의 '프로젝트 보기'로 저장 프로젝트를 열었을 때 T-3, T-5, A-1에서 별도 정적 활동 환영 메시지가 라이브 대화에 들어왔다. A-1은 엔진 제시와 일반 채팅 제시가 서로 다른 활동 요청을 보여 주었다. 실행 화면은 진행 중인데 프로젝트 채팅에는 'AI 응답이 끊겼습니다' 재시도 UI도 표시됐다.

근거: `ChatPanel.tsx:2425` 환영 effect는 실행 중인 `demoRun`을 제외하지 않는다. 엔진의 활동 전환·메시지 저장 사이에 일반 채팅이 개입할 수 있다.

검증 중 추가 오염을 줄이기 위해 산출물 확인 후 프로젝트 관찰 탭을 닫고 실행 탭만 유지했다. 자동 삽입된 메시지는 임의 삭제하지 않았다.

권고: 라이브 데모는 읽기 전용 관찰 모드로 분리하고, 환영·응답 재시도·팀 활동 이동·공동 편집 동작을 실행 상태와 조정한다.

### P1. 실제 사람 교사의 개입은 라이브 런에 반영되지 않는다

현재 확인한 것은 **교사 역할 AI ↔ 교사 역할 AI ↔ 총괄 AI**이다. 실제 사람 교사와 협업하는 대화 루프가 아니다. 실행 엔진의 `discussion`은 자체 요청 결과만 추가하며 현재 활동 중 Firestore의 사람 발언을 다시 읽지 않는다. 프로젝트 일반 채팅에 입력창이 있어도 엔진에는 전달되지 않는다.

권고: 사람 참여형과 전체 AI 시뮬레이션을 명확히 구분한다. 사람 참여형은 입력 대기·발언 반영·승인·재개를 같은 실행 상태기계에 연결해야 한다.

### P2. 문맥 축약으로 앞선 원칙과 근거가 사라진다

`run.ts:81`은 최근 10개 산출물, 섹션별 앞 700자만 전달한다. 마지막 E-2에서는 T단계 산출물 전체가 제외되며 과거 교사 대화도 제공되지 않는다. 뒤에 적힌 접근성 조건·소수 의견이 잘릴 수 있어, 실제 협력 과정의 기여·갈등 조정에 관한 성찰 근거가 부족하다.

권고: 비전·원칙·역할·학습자 제약은 고정 문맥으로 유지하고, 결정 및 이견 기록에 근거 메시지 링크를 보존한다.

### P2. 내부 출력 메타데이터가 대화에 노출된다

실제 T-2 말미에 `artifact: null`, T-4에 'artifact와 stageReport는 현재 없습니다', A-1에 `artifact and stageReport are null`이 보였다. JSON 바깥 유효성만으로 자연어 본문의 내부 형식 설명까지 막지는 못한다.

권고: 콘텐츠 전용 출력 지시와 본문 검증/재생성을 추가한다.

### P1. 자료 개발과 수업 실행은 실제 결과 생성까지 도달하지 않았다

완료 후 DI-1 상세 산출물을 열어 확인한 내용은 '합성 강우 데이터 샘플 초안', '학생용 기록지 초안', '교사용 요약 카드' 등의 목록과 요구사항이었다. 25개 데이터의 실제 값, 완성된 발문 3개, 예시 답안, 다운로드 가능한 CSV/PDF는 해당 결과에서 확인되지 않았다. 예를 들어 '발문 템플릿 3개 및 모델 문장 예시 1개'라는 요구만 있고 문장 자체가 없다. 자료·담당·일정·학생 관점 검토 표도 없다.

DI-2 '주요 상황 기록'은 교사들의 설계 합의를 요약한다. 수업의 시점별 관찰·학생 반응·증거 위치가 없다. 데이터가 합성이라는 표기는 유지되지만, **모의 수업을 실제로 시뮬레이션한 기록**과는 다르다. E-2도 T단계 운영 합의와 실제 발언 기여를 대조하지 않고 실행 전 자료 배포 규칙 조정으로 끝났다.

권고: 자료 목록 → 자료 본문/파일 제작 → 동료 검토 → 버전 수정 → 명시적으로 표시된 모의 실행 증거 생성 → 그 증거 기반 성찰로 연결한다. 실행하지 않은 행위를 완료로 기록하지 않는다.

## 운영 안정성: 코드로 확인한 위험, 실제 장애 유발 시험은 하지 않음

- 실행 잠금은 탭 로컬 ref이므로 같은 실행 URL을 두 탭에서 열면 중복 실행을 막는 분산 lease가 없다.
- 현재 활동 재개 시 `deleteActivityMessages`로 해당 활동 메시지를 비운다. 사용자의 별도 기록까지 보존되는지 보장되지 않는다.
- 동시 작업 중 한 worker가 실패해 `Promise.all`이 반환해도 다른 worker를 즉시 취소하는 공통 처리가 없다. mock 동작 테스트에서는 전체 실행이 오류로 반환된 뒤 남은 worker가 교사 2·3의 발언을 추가 저장하는 현상까지 재현했다. 실제 프로젝트에 장애를 유발하지 않았다.
- 브라우저 주도 실행이므로 탭을 닫으면 독립 백그라운드 작업으로 완주하지 않는다.
